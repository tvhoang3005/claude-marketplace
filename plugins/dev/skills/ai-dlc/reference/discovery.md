# Discovery

Challenge a vague idea before any engineering starts. Ask the user these six questions, one or two at a time, and push back on hypothetical answers:

1. **What's the pain?** Specific recent examples, not hypotheticals.
2. **Who feels it?** Persona, how often, how badly.
3. **What exists today?** Current workarounds and why they fall short.
4. **What's the smallest version?** The narrowest wedge that removes real pain.
5. **What's the 10x version?** Where this could go if it works.
6. **What breaks if we're wrong?** How we'd know, and what it costs.

## Output: `discovery.md`

```markdown
# Discovery: <work-id>

## Problem (reframed)
One paragraph in the user's terms.

## Answers
1. Pain: ...
2. Who: ...
3. Today: ...
4. Smallest version: ...
5. 10x version: ...
6. Risk if wrong: ...

## Recommendation
The narrowest viable approach, and what is explicitly out of scope.
```

At the checkpoint, offer to continue with Plan using the recommendation as the request.
